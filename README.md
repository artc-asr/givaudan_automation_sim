# givaudan_automation_sim

Shelf-aisle simulation (two shelves, 494 trays, 16 796 vials) with rochestra robots
spawned between the shelves.

| Package | What |
|---|---|
| `src/shelf_world` | the world (generated by `scripts/generate_world.py`), Harmonic + Fortress copies |
| `src/givaudan_bringup` | `robot_in_aisle.launch.py`: one rochestra robot in the aisle, facing a shelf |
| `reachability/` | highest shelf level per robot and task, with cuRobo (no ROS); see its README |
| `src/external/` | rochestra and its source deps, imported from `repos/main.repos` (not committed) |
| `deps/harmonic`, `deps/fortress` | per-Gazebo-version underlays from `repos/*.repos` (not committed) |

## Setup (Ubuntu 22.04, ROS 2 Humble, Gazebo Harmonic + Fortress)

```bash
./scripts/setup_workspace.sh          # vcs import (pinned) + build, ~4 min
```

## Run

One Gazebo version per terminal: vb2, g1 and rby1 run on Harmonic, moz1 on Fortress.

```bash
source scripts/env.sh harmonic
ros2 launch givaudan_bringup robot_in_aisle.launch.py robot:=rby1 face:=A   # rby1 = Model M (mecanum)
ros2 launch givaudan_bringup robot_in_aisle.launch.py robot:=vb2  face:=B
ros2 launch givaudan_bringup robot_in_aisle.launch.py robot:=g1   face:=B gui:=false

source scripts/env.sh fortress        # new terminal
ros2 launch givaudan_bringup robot_in_aisle.launch.py robot:=moz1 face:=B   # moz1: face B only (rochestra has no pose args yet)
```

`face:=B` = yaw 0 (towards shelf B, x > 0), `face:=A` = yaw pi. `x:=`/`y:=` move the robot (default aisle centre).
Each robot gets the physics step of its own rochestra world (see `PHYSICS` in the launch file).

Check a spawn headless (pose from Gazebo, RTF, controllers): `scripts/check_spawn.sh rby1 A`.

## Known issue

The 494 tray models (2505 visuals) are slow to render for the robots' cameras and lidars:
real-time factor vb2 0.12, g1 0.21, rby1 0.43, moz1 ~0 (software rendering, its controllers time out).
Without the trays vb2 runs at 0.86.
